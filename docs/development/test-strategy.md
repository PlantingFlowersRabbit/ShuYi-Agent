# v0.13 测试策略

## 目标

把 `docs/development/acceptance-standard.md` 中的 AC 转成可执行测试、可观察证据或人工复核清单。

## 自动测试优先级

### 单元测试

- 章节正则：给定 `assets/samples/novels/hongloumeng_pg24264_excerpt.txt`，能识别中文章节标题。
- 真实章节正则：给定 `/Users/gaojing/Downloads/真实测试样本/小说/这个地下城长蘑菇了.txt`，能识别 `1.标题` 数字编号章节。
- 段落正则：能按空行或固定格式拆段，不吞文本。
- 音色资源：默认资源可加载，支持 create / update / delete，包含音色名称、描述、语音具体内容和参考音频。
- 模型配置：LLM/TTS 配置可读取和更新，不暴露真实 API key。
- LLM JSON schema：缺字段、错类型、非法枚举都失败。
- 文本守恒：原段落与 utterances 拼接归一化后必须相等。
- provider registry：SiliconFlow 和 DeepSeek 预留配置能被解析。
- TTS request：voice cloning 和 voice design 的必填字段检查。
- manifest：本地资源路径存在、许可证字段完整、Common Voice 不出现在本地文件列表。

### 集成测试

- 导入小说到章节列表。
- 上传小说进度条随读取阶段更新。
- 章节划分进度条随轻量章节索引阶段更新。
- 左侧小说章节区只渲染开头预览，不把完整大文件绑定到 textarea。
- 点击“划分章节”之前，右侧只展示空态，不展示具体章节内容。
- 选择章节到段落模块。
- 选择章节后才从完整文本中提取该章正文并拆分段落。
- 确认段落后启用语句划分。
- 语句划分进度条按段落处理数量更新。
- 单条音频生成触发语音生成进度条更新。
- 子语句嵌套在来源段落内。
- 音色资源库变更后，角色音色选择器同步更新。
- 模型输出经 JSON repair 和文本守恒校验。
- 子语句角色选择器跟随角色卡变化。
- 单条 utterance 发起音频生成并记录 VoiceJob；服务不可用时返回可播放占位音频。

### E2E / 真实环境测试

- 前端 Playwright：Unitale 风格三页面、章节选择、延迟章节正文加载、段落折叠、删除、编辑、确认门禁、段落内嵌 utterance、左右独立滚动。
- 后端真实 API：解析、角色、语句划分、TTS 请求。
- 本地 TTS：启动服务，检查 `/health`，生成可解码 wav。
- 音频取证：保存 `ffprobe` 输出、文件大小、时长和路径。
- 真实音色样本：检查 `年轻男`、`御姐音`、`播音腔女`、`男声旁白` 的 mp3 和 `语音内容.txt`。

## 人工复核

人工复核适用于：

- 视觉布局是否符合两栏工作台。
- Unitale 风格是否落实到浅色 slate 背景、tab、8-12px 圆角和小号高字重按钮。
- 模型划分是否达到可校正草稿质量。
- 真实音色样本是否能播放，且生成音色替身没有被误称为真实 voice design 质量。

人工复核必须留下：

- 截图或录屏。
- 输入文件和选择章节。
- 运行命令。
- 观察结论。
- 未通过项。

## 覆盖映射要求

`test-author` 写测试时，每条用例必须标注覆盖的 AC 编号。

`acceptance-checker` 核对时，必须输出：

- AC 编号。
- 对应测试或人工检查点。
- 覆盖状态：已覆盖 / 假覆盖 / 未覆盖 / 覆盖存疑。
- 缺口清单。
