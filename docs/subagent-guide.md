# 子 Agent 使用说明

主 Agent 负责方向、拆分、整合和最终判断；子 Agent 只负责边界清楚、输入明确、结果可检查的小任务。

## 什么时候可以开子 Agent

- 任务可以拆成互不影响的小块。
- 每个小块都有明确输入、目标和完成标准。
- 子 Agent 只需要查看或修改少量文件。
- 子 Agent 的结果可以通过测试、日志、截图、音频文件或文档检查。
- 多个任务不会同时修改同一批文件。

适合任务：

- 根据验收标准写测试用例。
- 核对每条 AC 是否有测试覆盖。
- 实现一个独立 UI 模块或后端服务。
- 只读检查语句划分合约是否被遵守。
- 只读检查音频样本和输出是否可追溯。
- 复核代码是否违反架构边界。

## 什么时候不要开子 Agent

- spec 或验收标准还没读清楚。
- 任务边界模糊，只知道“大概做一个功能”。
- 任务需要用户拍板产品取舍。
- 多个子 Agent 会同时改同一个文件。
- 当前缺少测试、日志、截图或可复现步骤，无法判断结果。
- 问题看起来分散但可能来自同一个根因。

## 派发前必须准备的信息

主 Agent 派发任务前必须明确：

- 本次任务来自哪个 spec。
- 本次任务对应哪些验收标准。
- 目标是什么。
- 可以读取哪些文件。
- 可以修改哪些文件。
- 禁止修改哪些文件。
- 完成后必须返回什么。
- 用什么方式验证结果。

## 子 Agent 返回格式

子 Agent 必须返回：

- 做了什么。
- 改了哪些文件。
- 如何验证。
- 覆盖哪些验收标准。
- 是否完全满足任务要求。
- 还存在哪些风险或未验证点。

如果没有完成，必须说明：

- 卡在哪里。
- 已经查过什么。
- 为什么继续不下去。
- 需要主 Agent 补什么上下文。

## 并行规则

可以并行：

- 多个只读调查。
- 检查不同目录或不同文档。
- 修改互不重叠的文件。

不要并行：

- 多个子 Agent 改同一个实现文件。
- 多个子 Agent 改同一个 docs 索引。
- 一个任务结果会决定另一个任务做法。
- 当前问题可能来自同一个根因。

并行任务结束后，主 Agent 必须统一检查 diff、运行验证，并确认没有互相覆盖。
