# NovelVoice-Agent v0.11 Harness Spec

## Goal

v0.11 turns the current manual collaboration workbench into a Unitale-inspired light UI with three pages:
main workbench, voice resource library, and model configuration.

The release keeps the human-led workflow: users upload a novel, confirm chapter and paragraph structure, then run
editable utterance segmentation and audio preview. Model output remains a draft and must stay manually editable.

## Main Page

- Use the v0.10/v0.1 home workflow as the main page, with a light slate Unitale-style layout.
- Left side starts with the novel chapter area: `上传小说`, `确认划分章节`, and a scrollable chapter list.
- The novel chapter area must show only a short opening preview of the uploaded novel. The full uploaded text must stay
  in application state for parsing, but must not be rendered into a large controlled textarea.
- The main page shows progress bars for novel upload, utterance segmentation, and voice generation.
- Chapter parsing must support both Chinese headings such as `第一章 标题` and numeric headings such as
  `1.变成蘑菇的公爵千金`.
- The left side role list is driven by the voice resource library, not by the old three smoke placeholder role cards.
- Each role shows an editable role name, a voice selector by voice name, a voice playback control, the voice description,
  and the exact reference transcript.
- The right side shows paragraph cards. Utterance editors are nested inside their source paragraph, not rendered as a
  separate global list.

## Voice Resource Library

- The library lists voice resources with name, description, reference transcript, and playable reference audio.
- Users can add resources by entering voice name, description, transcript, and reference audio path.
- Users can generate a resource from name and description. v0.11 may use a deterministic local substitute for generated
  transcript/audio path, but must not claim real voice design quality unless a real provider was run.
- Users can edit and save resource fields.
- Users can select resources and delete them from the current resource list.

## Model Configuration

- The model page centralizes LLM and TTS provider configuration.
- LLM fields include provider, base URL, model, API-key environment variable name, timeout, and retry count.
- TTS fields include provider, base URL, model path environment variable, device environment variable, and timeout.
- The UI and tests must not contain API-key values. Only environment variable names may be displayed.

## Acceptance

- Existing text conservation, provider registry, TTS request validation, and real-environment evidence rules still apply.
- Mock or deterministic substitutes are allowed for unit tests only and must be labeled as substitutes in verification docs.
- UI work requires screenshot evidence before claiming completion.
