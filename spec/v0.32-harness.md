# NovelVoice-Agent v0.3.2 Harness Spec

## Goal

v0.3.2 fixes two AI role matching regressions: dialogue-plus-speech-tag utterances must be segmented before batch role matching, and deleting one paragraph must not clear role-matched utterances from the rest of the chapter.

## Required Behavior

- `AI角色匹配` must detect pending utterances that mix quoted dialogue with trailing narration such as `“都怪你多嘴，她认出我们了。”佩罗恼火道。` before sending statements to the batch role-selection LLM.
- When this structure is detected, `AI角色匹配` must call the existing AI statement segmentation service first, replace the original mixed utterance with the segmented utterances, and then run batch role matching on those segmented utterances.
- After segmentation and re-matching, quoted dialogue can be assigned to the speaking role, but the trailing speech tag / narration fragment, for example `佩罗恼火道。`, must be assigned to the narrator role.
- Existing batch role-selection safeguards still apply: existing roles are never overwritten, invalid JSON writes nothing, and `needs_split` falls back through the existing AI statement segmentation service.
- Deleting a paragraph from the right-hand chapter UI must only mark that paragraph deleted and remove that paragraph's utterance cache.
- Deleting one paragraph must preserve all other paragraphs' `AI角色匹配` results, role assignments, and generated-state bookkeeping.
- Deleting one paragraph must not call the full AI workflow reset path or clear `utterancesByParagraph` for the entire chapter.

## Acceptance

- `pyproject.toml`, `frontend/package.json`, and `frontend/package-lock.json` report `0.3.2`.
- The browser title and main UI title report `NovelVoice-Agent v0.3.2`.
- Backend tests cover that the mixed utterance is segmented before the first batch role-selection call; the model must only see the segmented statements, and the result must be `["peruo", "narrator"]`.
- Frontend repository checks confirm paragraph deletion uses a dedicated `deleteParagraph` path that removes only the deleted paragraph's utterances.
- Existing v0.3.1 split-button workflow and v0.3.0 batch dubbing/export tests continue to pass.
