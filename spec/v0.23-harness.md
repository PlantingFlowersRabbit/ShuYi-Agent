# NovelVoice-Agent v0.23 Harness Spec

## Goal

v0.23 fixes local Qwen3-TTS startup feedback so the UI cannot report success merely because the server process was
spawned. Startup success means the service health check responds after model loading and confirms VoiceDesign is
available.

## Local TTS Startup

- The model configuration page keeps separate Base and VoiceDesign model weight paths.
- Clicking `启动服务` starts the local TTS server only when no ready service is already available at `BASE_URL`.
- The API waits for `/health` before returning success.
- `/health` must report `voice_clone=true`, `voice_design=true`, and `voice_design_capable=true`.
- If the process is spawned but health is unreachable, still loading, or lacks VoiceDesign capability, the API returns a
  failure/loading response rather than “启动成功”.

## UI Feedback

- The model configuration page shows `启动服务进度` while waiting for Base and VoiceDesign model loading.
- The start button is disabled while startup is in progress.
- Success copy must mention that model loading is complete.

## Acceptance

- `生成资源到资源库列表 -> 生成音色` no longer follows a false-success startup path that later hits
  `<urlopen error [Errno 61] Connection refused>`.
- Main-page `音频生成` no longer relies on a startup status that was returned before the local TTS service became
  reachable.
- Main-page voice cloning preserves the original reference audio extension in the local JSON request, so MP3 reference
  clips are not written to temporary `.wav` files with mismatched content.
- Fallback placeholder wav behavior remains available when the user has not started a ready local TTS service, but it is
  no longer preceded by a false startup success message.
