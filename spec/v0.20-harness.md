# NovelVoice-Agent v0.20 Harness Spec

## Goal

v0.20 adds an AI chapter splitting agent for arbitrary txt novels. The workbench keeps the v0.12 lazy-loading behavior,
but the visible chapter split action is now `AI章节划分` and is backed by a script-reuse-first agent.

## Agent Workflow

- Clicking `AI章节划分` posts the full novel text to `/api/novels/ai-chapter-split`.
- The backend agent checks `scripts/chapter_parsers/` for existing Python parser scripts before calling a model.
- Existing scripts read full txt from stdin and output strict JSON chapters.
- A result is accepted only after rule validation: non-empty chapter list, sequential chapter ids, titles, bodies, and
  rejection of one-chapter output when multiple repeated heading-like lines are present.
- If existing scripts fail or validate incorrectly, the agent invokes a chapter splitting skill.
- The skill uses LangChain with DeepSeek `base_url="https://api.deepseek.com"` and `model="deepseek-v4-flash"`.
- The skill inspects the novel sample, creates a Python parser script with a Chinese comment describing the recognized
  format, and returns only runnable Python code.
- Generated scripts are saved as `scripts/chapter_parsers/agent_generated_*.py` for future reuse and are gitignored.

## Frontend

- The old `划分章节` label is renamed to `AI章节划分`.
- Uploading txt only stores the full text and renders a short preview; it does not eagerly parse or render chapter bodies.
- If the AI endpoint is unavailable, the UI may fall back to the existing local chapter-index parser and clearly report
  that fallback in status text.
- The model configuration page exposes `AI章节划分智能体` with Base URL, model name, and api_key fields.

## Acceptance

- `langchain` and `langchain-openai` are backend dependencies.
- The default model config includes `chapter_agent.base_url=https://api.deepseek.com` and
  `chapter_agent.model=deepseek-v4-flash`.
- `/api/novels/ai-chapter-split` updates backend chapters and workbenches after a validated split.
- Existing parser scripts are reused before the DeepSeek skill is called.
- Invalid parser output triggers reflection and new script creation.
- No API key is committed to the repository.
