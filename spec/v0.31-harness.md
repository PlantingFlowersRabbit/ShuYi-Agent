# NovelVoice-Agent v0.3.1 Harness Spec

## Goal

v0.3.1 splits the former `AI一键分析` user flow into two explicit chapter actions: `AI角色分析` for role and voice preparation, and `AI角色匹配` for statement role selection.

## Required Behavior

- `AI角色分析` starts the existing LangGraph role-analysis stage for the selected chapter.
- The role-analysis stage keeps the v0.3.0 automation: it analyzes candidates, adds or updates roles, matches existing voices or generates suitable voices, binds voice resources, and surfaces candidate evidence for human review.
- `AI角色匹配` resumes the same workflow thread after role review and performs the previous statement role-selection stage.
- Role matching only writes blank-role statements and preserves existing `role_id` / `speaker_role_id` values.
- Role matching keeps the v0.3.0 batch behavior: one batch role-selection path for multiple blank statements, `needs_split` fallback through existing AI statement segmentation, streamed `role_selected` events, and no half-write on invalid JSON.
- The UI must not expose the old `AI一键分析` entry or `角色列表确认完成` action label in the main flow.
- `一键生成配音` and `一键导出` remain separate follow-up actions; role matching must not automatically generate audio.

## Acceptance

- `pyproject.toml`, `frontend/package.json`, and `frontend/package-lock.json` report `0.3.1`.
- The browser title and main UI title report `NovelVoice-Agent v0.3.1`.
- Frontend repository checks confirm `AI角色分析` and `AI角色匹配` controls are visible, call distinct handlers, and no longer contain the old `AI一键分析` or `角色列表确认完成` labels.
- Backend workflow messages for the resume stage use `AI角色匹配` terminology while preserving the existing API contract.
- Existing v0.3.0 batch role-selection, dubbing, export, and deletion tests continue to pass.
